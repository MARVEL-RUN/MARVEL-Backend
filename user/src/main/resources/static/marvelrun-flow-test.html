MARVEL RUN · 01–07 통합 API

개인·단체 신청 흐름 테스트

신청 → 수정·참가 취소 → 서버 주문으로 결제. API 입력을 정확히 확인할 수 있도록 요청 본문은 편집 가능한 JSON으로 제공합니다.

실제 API를 호출하는 테스트 도구입니다. 테스트 서버·테스트 대회·Toss 테스트 클라이언트 키를 사용하세요. 환불은 수정·취소 API 내부에서 실행되며 별도 환불 버튼은 없습니다.

1. 연결 설정

설정·대상 ID·주문만 이 탭의 sessionStorage에 저장합니다. 비밀번호·클라이언트 키·명단은 저장하지 않습니다. 결제 복귀 후 수정하려면 본인확인 정보를 다시 입력하세요. 조회는 버튼을 눌렀을 때만 실행합니다.

처음 실행할 때
  1. 이 파일을 기존 HTML과 같은 정적 파일 위치에 두고 HTTP(S) 주소로 여세요. 파일 더블클릭(file://)은 결제 복귀용으로 지원하지 않습니다.
  2. 기본 URL의 /api는 기존 HTML 기준 기본값입니다. 실제 context-path/프록시에 맞추세요. 신청은 /v1/public, 선택지·승인은 /public입니다.
  3. 클라이언트 키만 입력합니다. 시크릿 키는 입력하지 않습니다. 테스트 결제위젯용 키와 설정된 UI 키를 사용하세요.
  4. 아래 JSON의 ID·개인정보·비밀번호를 바꾸고 요청을 보냅니다. 생성 후 ‘생성/수정 결과로 수정 본문 채우기’를 누르면 이어서 수정할 수 있습니다.
  5. 결제 인증 복귀 후에는 하단 ‘백엔드 승인 요청’을 직접 눌러야 승인됩니다. 페이지 재방문 시 자동 승인하지 않습니다.

다른 출처에서 실행하면 서버 CORS 설정이 필요할 수 있습니다. 이 HTML은 서버 보안 설정을 바꾸지 않습니다. 브라우저에 보이는 명단은 DB 최신 조회 결과가 아닙니다. 단체 수정으로 새 참가자를 추가한 후에는 응답에 이름-ID 대응이 없어, 다음 수정 전에 조회/DB에서 신규 신청 ID를 확인해야 합니다. ‘확인필요’ 표시는 실제 ID로 바꾸세요.

종목·기념품 조회 결과
아직 조회하지 않았습니다.

2. 신청·수정·참가 취소

개인 수정의 access는 DB에 저장된 현재 정보, 바깥쪽 정보는 변경할 값입니다. 생년월일 YYYY-MM-DD, 성별 M/F, selectedSouvenirList는 [{"souvenirId":"…","selectedSize":"M"}] 형식입니다. 신규 보호자 생년월일·전화번호 필드는 아직 포함하지 않습니다.

3. 서버가 만든 주문으로 한 번 결제

신규 참가비와 기존 참가자 추가금이 합쳐진 서버 orders[0]를 그대로 사용합니다. 환불액과 상계하지 않습니다. 금액을 직접 입력하거나 합산하지 않습니다.

준비된 주문 없음
주문 응답을 기다립니다.
refunds의 PROCESSING/UNKNOWN은 확인 중이므로 결제창을 열지 않습니다. FAILED는 환불 미완료입니다. 취소 응답에는 과거 환불 이력도 포함되므로 금액을 합쳐 ‘이번 환불액’으로 표시하지 않습니다.

4. Toss 복귀 및 백엔드 승인

결제 인증 복귀 전입니다.

Toss 인증 복귀만으로 신청·결제 완료가 아닙니다. 서버 processStatus와 참가자 상태를 확인하세요. 통신 오류·CONFIRMING·UNKNOWN은 실패 확정이 아니므로 신규 결제로 우회하지 마세요.

빠른 확인 순서

  1. 개인 신청 → 결제 → 개인정보만 수정 → 가격 상승 수정과 추가 결제 → 가격 하락 수정의 환불 결과 → 개인 취소.
  2. 단체 신청 → 결제 → 기존 구성원 종목 변경 + 새 구성원 추가 + 일부 제거 → 반환된 주문 한 번 결제 → 단체 전체 취소.
  3. 미납 신청 취소, 유효 READY 재준비, 실패 확정 주문 재준비도 별도 확인합니다. 진행·불명 상태를 실패로 취급하지 않습니다.

현재 구현은 추가 결제 전에도 종목·정원이 수정되는 모델입니다. ‘옛 종목 확정 유지 + 새 종목 임시 확보’ 모델은 별도 예정 작업이며 이 페이지가 그 동작을 구현하지 않습니다.
